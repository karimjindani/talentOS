## Notes

- The Ops console (`apps/ops`) is host-run (`npm run ops:start`), not part of `docker-compose.yml`
  — it must be running locally for the `ops` regression area (and therefore `regression:all`) to
  pass. Confirmed running before the final gate run above.
- Manual verification of the apply-time photo upload also surfaced and fixed an unrelated,
  pre-existing build issue: `ApplyUploadFields.tsx` originally carried an
  `// eslint-disable-next-line @next/next/no-img-element` comment referencing a lint rule this
  repo's ESLint config doesn't register (no `@next/next` plugin is configured here). Disabling a
  nonexistent rule is itself a lint error under this project's ESLint version, which silently
  failed the applicant `next build` step inside Docker while the outer `docker compose build`
  command still reported exit code 0 — so earlier "successful" container rebuilds during this
  iteration were actually still serving the previous image. Removed the stale disable comment;
  confirmed via a `--no-cache` rebuild that the new code was actually present in the built image
  before re-verifying in the browser.
- Separately (not part of this iteration's shipped scope), a realistic local seed graduate
  ("Waseem Ali", program AI-Native Software Engineering, slug `waseem-ali`) was created via the
  real `createOrUpdateGraduateProfile`/apply flow to visually confirm the carry-through end-to-end
  on the public graduate directory page — not a regression scenario, pure local dev data.
