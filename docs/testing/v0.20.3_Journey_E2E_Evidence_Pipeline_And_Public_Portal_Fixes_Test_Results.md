## Notes

**A real defect was found and fixed while gathering this document's own evidence.** The first full
`npm run journeys` run for this test-results doc hung on `applicant-arc` and two `docs-only`
admin-portal blocks, each running the full 300s test timeout before failing — reproducible 3/3.
Rather than record that as a pre-existing Known Gap, it was root-caused live:

1. A standalone reproduction using the real `provisionJourneyTenant`/`provisionJourneyAdminIdentity`
   code, in an isolated single-context browser, converged and logged in correctly in ~30s — ruling
   out the login mechanism itself.
2. The failure only appeared inside the real multi-actor fixture (a second browser context opened
   while the first was still alive). Direct network-event instrumentation on the reviewer's page
   found a duplicate `GET /api/auth/session` fired within the same tick (next-auth's mount-time fetch
   racing its refetch-on-window-focus fetch, the latter triggered by the page regaining focus after
   the Keycloak redirect). One of the two never received a completion event in Playwright's own
   request-tracking ledger — a Chromium/CDP dedup quirk on identical concurrent GETs, confirmed not
   an application-side hang: `pg_stat_activity` showed only idle connections and `docker stats`
   showed ~0% CPU across every container throughout the "hang."
3. With that ledger entry permanently stuck, `networkidle` never fired again for that page, and none
   of the three call sites using `page.waitForLoadState("networkidle")`
   (`fixtures/actors.ts`'s login loop, `applicant-arc.spec.ts`'s `settledClick`, `docs-only.spec.ts`'s
   own duplicate `settle`) had an explicit timeout — in this environment that call has no effective
   default bound, so each one waited until the whole test's 300s budget ran out.

Fixed by bounding all three to a 5s timeout with the rejection swallowed, matching the one call site
that already had this protection. Verified twice for reproducibility: before the fix, 3/9 failed
every run (3 separate runs, same failure point each time); after the fix, 8/9 passed with 0 failures
across 2 separate full runs. See `D-103` for the complete root-cause writeup.

**`docs-only.spec.ts` does not use the `journey` fixture**, so it produces no
`.ops/journey-results/*.json` entry — its evidence is the captured screenshots themselves
(`docs/user-guides/screenshots/`) plus Playwright's own HTML/JSON report, not a `JourneyRecord`. This
is by design (it replaces the old screenshot-only `capture-screenshots.ts`, not a step-asserting
journey), not a gap.
