## Summary

All five gates pass. Unit coverage grew from 676 to 729 tests across 57 files, and
`npm run regression:all` is green at 41/42 with one pre-existing documented skip. The regression suite
was the decisive check this iteration: its first run failed 12 of 42 scenarios, every failure caused by
this iteration's own changes — 11 by the new journal start-date rule invalidating fixture dates, and
one by a fixture that created a `ProgramTask` without the now-required `missionId`. A third failure
surfaced a genuine contract change rather than a fixture defect: "a repeat attempt retains week tasks"
is no longer true, because a repeat moves to a different mission carrying its own tasks. That
assertion was rewritten to encode the new contract, plus a new check that the earlier mission's
completion is not erased.

## Notes

- **One skip, pre-existing:** `storage: Storage browser upload/download scenario` — documented as not
  yet automated and unchanged by this iteration.
- **Regression fixtures now set an explicit acceptance date.** `createSubmissionFixture` backdates
  `acceptedAt` to a constant, and the eight directly-built `missionAssignment.create` fixtures set
  `assignedAt`/`acceptedAt` explicitly. Without this, journal-writing scenarios had no valid date
  window: entries may not pre-date the mission start nor be in the future, leaving exactly one usable
  date, which collides with the one-entry-per-day rule. The Thursday-deadline scenario opts out with
  `backdateAcceptanceTo: null` because it asserts on the acceptance → deadline calculation.
- **Regression data cleanup was required before capturing screenshots.** Accumulated runs had left 163
  regression missions in the local database and the first screenshot pass captured fixture data;
  `npm run ops:cleanup-regression` removed 1,311 marked rows and the shots were retaken against demo
  data.
- **Backfilled review rounds have no feedback text.** `audit_logs` recorded decisions but never
  feedback, so pre-`v0.20.0` rounds other than the last show "No feedback recorded." This is visible
  in the guide screenshot and is a permanent property of historical rows.
- **All user-guide screenshots were regenerated against this build.** The previous 01–27 set predated
  several shipped changes and was deleted rather than patched; `npm run` of
  `scripts/user-guide/capture-screenshots.ts` now produces **34 shots with zero skips**, every one
  captured within the same session as this baseline. Two numbers were retired rather than renumbered,
  so existing references keep working:
  - `25-admin-operations.png` — the Back Office Operations page was removed in `c562e0f`; the guide
    section now documents only the standalone Ops Console. The script had still been capturing the
    dead route.
  - `23-admin-submission-review.png` — a documented skip since `v0.16.1`, now permanently
    unreachable because the mission detail page no longer lists submissions (`v0.20.0`). Submission
    review is captured as `35-admin-review-history.png` via the Submissions list, which is the real
    route.
- **Capture-run data footprint:** the `apply` section registers a fresh Keycloak applicant each run by
  design, so a full capture adds one user and one application (8→9 and 4→5 here). Mission, program and
  tenant counts were unchanged, confirmed by before/after snapshots.
- **Deferred scenarios** (dangling-repeat rescue, grouped Journal, Markdown import, and the
  week-advance half of the enrolled-with-no-mission scenario) are recorded in
  `docs/Regression_Scenarios.md` Known Gaps, per `docs/sdlc.md`.
- **Manual portal verification** used the repo's own Playwright against the running Docker stack. Each
  script snapshotted the database beforehand and diffed table counts afterwards; all runs reported a
  clean restore.
