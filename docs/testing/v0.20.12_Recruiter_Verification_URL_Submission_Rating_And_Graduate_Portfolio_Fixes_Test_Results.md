## Notes

- No database schema change — `Submission.rating` stays `Float`; integer enforcement is at the application layer (`Number.isInteger`) in both the server action and DB `reviewSubmission`.
- The E2E journey and regression ratings were changed from decimals (4.2/4.5) to integers, and the journey's review-field interaction changed from `fill` to `selectOption` (the field is now a `<select>`).
- The verification-URL fix avoids `NEXT_PUBLIC_APPLICANT_URL`, which is inlined at build time and excluded from the Docker build via `.dockerignore`; `APP_BASE_DOMAIN` and `APPLICANT_PORT` are runtime env vars.
- Manual testing was performed against the running Docker stack on `localhost:3100` (applicant) and `localhost:3200` (admin).
