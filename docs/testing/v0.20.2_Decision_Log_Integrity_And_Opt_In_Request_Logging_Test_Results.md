# v0.20.2 Decision Log Integrity And Opt-In Request Logging Test Results

Date: 2026-08-13

## Summary

All five gates pass. The scenario suite ran locally against the rebuilt Docker stack: **53 scenarios,
52 passed, 0 failed, 1 skipped** (run `regression-20260813055040-db1f4b18`, 32.6s), matching `v0.20.1`'s
CI result exactly and confirming the middleware edit changed no observable behavior.

That last point was the risk worth spending effort on. `logRequest` is called at the top of both app
middlewares, which are the authorization boundary for the two portals — a mistake there would be an
access-control bug, not a logging bug. The two scenarios that would catch it both pass:
*"Applicant session cookie does not grant admin portal access (v0.20.1)"* (applicant portal 200, admin
portal 307) and the full `tenant` area, 9/9.

Because a stale Docker image would have made a green run meaningless, the running container was first
proven to contain the new code by observing its actual output rather than trusting the build.

## Notes

- **Proof the running image was not stale.** `docker compose logs` after the rebuild showed the new
  line format for `/` and `/dashboard` and nothing for `/favicon.svg`. The old `v0.20.1` code would have
  logged all three, so the observed output can only come from the new module. This matters because
  every regression result below depends on the container actually running the edited middleware.
- **The one skip is pre-existing and documented**: `storage: Storage browser upload/download scenario`,
  carried since `v0.18.3`.
- **Per-area totals** — admin 7, applicant 3, auth 6, dashboard 3, journal 4, missions 15, ops 2,
  programs 2, storage 1 (skipped), tenant 9, unit 1. Identical to `v0.20.1`'s CI artifact, which is the
  intended outcome for a correction iteration.
- **Scenario counts in the docs were wrong before this iteration**: `Regression_Scenarios.md` claimed 40
  in one place and 42 in another; the runner has 53. Corrected against both a structural parse of
  `run.ts` and the CI artifact's per-area totals, which agree.
- **No schema change**, so `Data_Model.md` and `Data_Dictionary.md` are unchanged and keep their
  `v0.20.1` headers. Recorded explicitly per `docs/sdlc.md` principle 6.
- **No user-facing surface change**, so neither user guide required an update this iteration.
- **`e2e-evidence` has not yet run on this branch** — it is gated to pull requests, so it will execute
  when the PR opens. The local run above used the same command (`npm run regression:all`) against the
  same stack topology.
