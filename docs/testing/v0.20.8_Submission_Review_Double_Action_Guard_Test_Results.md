Date: 2026-08-24

## Summary

## Notes

- Docker containers (`applicant`, `admin`) were rebuilt (`docker compose up -d --build`) against
  this branch and the DB confirmed on all 28 migrations (`prisma migrate status`) before running the
  full regression suite, so `regression:all` exercised the actual built images, not just source.
- The `ops` console (`apps/ops`, host-run via `npm run ops:start`, not part of docker-compose) was
  started for this run so the `ops` regression area (2 scenarios) could pass; per this repo's local
  dev topology it is not always running by default.
- The concurrent-review race guard (third scenario above) is proven at the unit level, not via a
  true two-transaction DB race in the regression runner — recorded as a Known Gap in
  `docs/Regression_Scenarios.md` per `docs/sdlc.md`'s "Deferred" option, since simulating genuine
  overlapping Postgres transactions isn't practical in the single-threaded regression harness. The
  guard clause itself (status-scoped `updateMany` + row-count check) mirrors the identical,
  already-proven-safe pattern `submitSubmission` uses for the same class of race.
- A related but separate bug — `computeMissionDeadline` landing on Thursday 23:59:59.999 **UTC**,
  which is already Friday morning in a UTC+5 timezone — was identified in the same review session
  and is intentionally tracked and shipped as its own iteration, `v0.20.9`, not bundled here.
