# v0.20.12 Recruiter Verification URL, Submission Rating Clarity, And Graduate Portfolio Fixes

Code version: `v0.20.12`

Previous baseline: `v0.20.11`

Plan status: Implemented

## Summary

Fixes three production issues and adds two UX improvements: (1) recruiter access verification emails now build tenant-aware links so they resolve to the correct tenant instead of the default `demo` tenant; (2) the auto-published graduate profile now carries the real average rating instead of a placeholder `0`; (3) the admin submission review rating is now integer-only with a clear rubric; (4) the recruiter request detail page drops the redundant Consent History and Graduate Information sections; (5) the graduate portfolio embeds the Loom walkthrough inline.

## Scope

- **Tenant-aware verification URL** (`apps/admin/app/api/recruiter-requests/[id]/route.ts`): new `buildTenantAppUrl` helper builds the applicant URL from `APP_BASE_DOMAIN` + `APPLICANT_PORT` + the tenant slug, so `NEXT_PUBLIC_APPLICANT_URL` (a build-time-inlined, `.dockerignore`-excluded variable) can no longer produce a wrong-tenant link. Applied to both approve and resend actions.
- **Real graduate rating on publish** (`packages/db/src/graduates.ts`, `packages/db/src/submissions.ts`, `apps/applicant/app/api/graduates/profile/acknowledge/route.ts`): `getCompletionSnapshot` is exported and accepts a transaction client; the auto-publish path in `reviewSubmission` recomputes `overallRating`, `graduationDate`, and `programId` before enabling the public profile; the acknowledge route carries the same values when training is complete.
- **Integer-only submission rating** (`apps/admin/app/missions/[id]/submissions/[submissionId]/page.tsx`, `apps/admin/app/missions/submission-actions.ts`, `packages/db/src/submissions.ts`): the free-form number input is replaced by a 1–5 select with a "View rating guide" rubric; both the server action and DB layer reject decimals via `Number.isInteger`.
- **Recruiter request detail page cleanup** (`apps/admin/app/recruiter-requests/[id]/page.tsx`): removed the Consent History section and the whole Graduate Information container.
- **Loom embed in portfolio** (`apps/applicant/app/graduates/[slug]/portfolio/page.tsx`): Loom share URLs are converted to embed URLs and rendered as an inline `iframe` in the Mission Evidence section, with an "Open full video" link; non-Loom URLs fall back to the external link chip.

## Out of Scope

- No database schema change — `Submission.rating` stays `Float` (integer enforced by validation, not column type).
- No submission decision/state-machine change.
- No new E2E journey; the existing `recruiter-access` journey gains one assertion for the Loom embed.

## Test Scenarios

### Scenario S1: Recruiter verification email link resolves to the correct tenant subdomain
- **Actor**: Recruiter who requested access to a graduate's portfolio.
- **Preconditions**: Request created on a non-default tenant (e.g. `paysyslabs`); admin approves.
- **Steps**: Open the verification email and click the link.
- **Expected result**: The URL is `http://{tenantSlug}.{APP_BASE_DOMAIN}:{APPLICANT_PORT}/graduates/verify?token=...` (e.g. `paysyslabs.lvh.me:3100`), not the default `demo` tenant. The verify route resolves the token correctly.
- **Automation**: Deferred — requires a running email + two-tenant stack; verified manually.

### Scenario S2: Recruiter request detail page no longer shows Consent History / Graduate Information
- **Actor**: Admin viewing a recruiter access request.
- **Preconditions**: A request exists.
- **Steps**: Open `/recruiter-requests/[id]`.
- **Expected result**: Only Recruiter Information, Review Information, and actions are shown. No "Graduate Information" or "Consent History" container.
- **Automation**: Deferred — UI structure; verified by code review + manual check.

### Scenario S3: Auto-published graduate profile shows the real average rating, not 0
- **Actor**: Applicant who completed 4 accepted missions with ratings.
- **Preconditions**: Profile was created as a placeholder (overallRating 0) and is auto-published when the 4th mission is accepted.
- **Steps**: Accept the 4th mission as a reviewer; view the public portfolio.
- **Expected result**: `overallRating` equals the average of the accepted week ratings, not `0`.
- **Automation**: Added this iteration — `submissions.test.ts` asserts `txGraduateProfileUpdateMany` is called with `overallRating: 4` (average of [4,5,3,4]) on auto-publish.

### Scenario S4: Submission rating is integer-only — decimals rejected
- **Actor**: Admin accepting a submission.
- **Preconditions**: A SUBMITTED submission exists.
- **Steps**: Submit a review with `rating = 4.5` (and 3.5, 2.7).
- **Expected result**: Rejected with "A whole-number rating from 1 to 5 is required when accepting a submission."
- **Automation**: Added this iteration — `submission-actions.test.ts` (action layer) and `submissions.test.ts` (DB layer) assert `rating: 4.5` is rejected.

### Scenario S5: Rating required on ACCEPTED, optional for other decisions
- **Actor**: Admin.
- **Preconditions**: A SUBMITTED submission exists.
- **Steps**: Attempt to accept without a rating; request changes / repeat with a rating.
- **Expected result**: Accept without rating throws; changes/repeat without rating succeed (rating stored as null).
- **Automation**: Added this iteration — `submissions.test.ts` and existing action tests cover rating-null behavior for NEEDS_REVISION / REPEAT.

### Scenario S6: Rating rubric is visible in the admin review UI
- **Actor**: Admin reviewing a submission.
- **Preconditions**: Review page loaded.
- **Steps**: Expand "View rating guide".
- **Expected result**: The 1–5 rubric and the five evaluation criteria (requirements, technical implementation, testing, evidence, competencies) are shown.
- **Automation**: Deferred — UI content; verified by code review + manual check.

### Scenario S7: Loom walkthrough is embedded inline in the portfolio Mission Evidence
- **Actor**: Recruiter viewing a graduate portfolio.
- **Preconditions**: Graduate has a valid `loomUrl` (share or embed link).
- **Steps**: Open the graduate portfolio.
- **Expected result**: The Loom video renders in an inline `iframe` with an "Open full video" link.
- **Automation**: Added this iteration — `recruiter-access.spec.ts` asserts `iframe[src^="https://www.loom.com/embed/"]` is visible on the portfolio.

### Scenario S8: Non-Loom or invalid URL falls back to the external link chip
- **Actor**: Recruiter viewing a graduate portfolio.
- **Preconditions**: Graduate has a `loomUrl` that is not a valid Loom share/embed URL (or is null).
- **Steps**: Open the portfolio.
- **Expected result**: The Loom Walkthrough renders as a plain external link chip, no iframe.
- **Automation**: Deferred — UI conditional; verified by code review.

## Security and Data Rules

- The verification URL is tenant-scoped by construction (tenant slug subdomain) — no cross-tenant token confusion.
- Rating validation is enforced on the server (action + DB), not only the UI.
- The Loom embed is a plain `iframe` to the public `www.loom.com/embed` domain — no user-controlled iframe src beyond the validated Loom host.
- No schema change; `Submission.rating` remains `Float` with integer enforcement at the application layer.
