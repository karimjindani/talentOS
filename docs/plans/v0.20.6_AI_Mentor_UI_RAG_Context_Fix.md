# v0.20.6 AI Mentor UI, RAG, Context Fix, And RBSE Unblock

Code version: `v0.20.6`

Previous baseline: `v0.20.5`

Plan status: Implemented

## Summary

The AI Mentor in the applicant portal was giving wrong answers (claiming Mission 1 was "completed" when it was never submitted), blocking legitimate questions ("tell me about mission 1" was caught by an overly broad RBSE filter), appending unwanted "Next step" follow-up prompts, and saying "I'm not sure" for any topic not in the hand-curated knowledge base. This iteration fixes the context accuracy, unblocks the RBSE, removes follow-up prompts, adds a build-time RAG layer over `docs/*.md` so the mentor auto-discovers new features, and upgrades the chat UI with per-message actions, mobile support, streaming-safe rendering, and conversation management.

## Scope

- **Context fix** (`lib/ai-context.ts`): add `missionStatus` field with per-mission readiness (assignment status, submission, journal count, task completion); rewrite `contextToPromptSection` with unambiguous labels so the LLM cannot misread "ACCEPTED" as "completed" or task % as mission completion; update `buildContextSignature` to include `missionStatus`.
- **RBSE fix** (`lib/ai-rbse.ts`): remove broad `"tell me about "` and `"explain about"` from `BLOCKED_TOPICS` — the precise `PERSONAL_NAME_PATTERNS` + `NAME_PATTERN_ALLOWLIST` already handle personal-name blocking.
- **System prompt fix** (`lib/ai.ts`): remove "Next step" / follow-up question instructions; add explicit "Do NOT end with a follow-up question" rule.
- **Stub fix** (`lib/ai.ts`): tips card only rendered when `additionalSnippets.length > 0`; title changed to "Related Resources".
- **MentorCard type** (`lib/ai.ts`): add `code` + `resource` kinds; add `link` to task cards.
- **Knowledge base expansion** (`lib/knowledge-base.ts`): add 6 curated entries (journal rules, mission lifecycle, tasks, submission workflow, applications, recruiter portal, calendar) — total 17.
- **RAG docs index** (`scripts/build-docs-index.mjs` + `data/docs-index.ts`): build-time indexer reads `docs/*.md` → 347 sections; `retrieveKnowledge` searches curated KB (Layer 1, boosted) + docs index (Layer 2, dedup by source); added to Dockerfile + `npm run build`.
- **Chat UI** (`page.tsx`, `MessageBubble.tsx`, `CardRenderer.tsx`): streaming-safe markdown; per-message actions (copy, regenerate, edit-and-resend, thumbs up/down); suggested questions send immediately; personalized welcome + context disclosure; mobile drawer; live clock; real maxLength; streaming perf fix; conversation search/rename/pin.
- **Context endpoint** (`route.ts`): `?context=1` mode returns applicant context summary.
- **Architecture doc** (`docs/AI_Mentor_Architecture_and_Concepts.md`): comprehensive doc covering all concepts and e2e flow.

## Out of Scope

- File/image attachment and voice input — explicitly deferred per user request.
- pgvector + embeddings for semantic retrieval — the current keyword-based RAG is the MVP; semantic retrieval is a future phase.
- Server-side persistence of mentor feedback (thumbs up/down) — currently localStorage only; a feedback table is a future enhancement.
- The uncommitted admin SidebarNav fix — separate concern, not part of this iteration.

- **Preconditions**: LLM configured (LiteLLM proxy reachable). Applicant has an ACCEPTED application.
- **Steps**: Applicant opens `/dashboard/mentor`, types "tell me about mission 1", sends.

- **Automation**: Deferred — requires a running LLM endpoint and seeded applicant data; covered by manual verification + the context unit tests (`ai-context.test.ts`) that assert `missionStatus` fields.

## Security and Data Rules

- The mentor API (`/api/ai/mentor`) requires authentication via `resolveTenantAccess()` — unauthenticated requests get 401.
- The applicant context is scoped by `tenantId` + `userId` — no cross-tenant data leakage.
- The RBSE blocks personal-name questions and off-topic questions before any LLM call — the LLM never sees blocked prompts.
- The `?context=1` endpoint requires the same auth as the mentor route.
- LLM API key (`GLM_Z_API_KEY`) is stored in `.env` (gitignored) and passed via Docker Compose environment — never committed to version control.
- The docs index is generated from `docs/*.md` at build time — no runtime filesystem access, no path traversal risk.
