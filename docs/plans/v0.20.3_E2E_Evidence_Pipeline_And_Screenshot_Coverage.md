# v0.20.3 E2E Evidence Pipeline And Screenshot Coverage Expansion

Code version: `v0.20.3`

Previous baseline: `v0.20.2`

Plan status: Implemented

## Summary

This iteration completes the E2E evidence pipeline by expanding Playwright screenshot coverage to
every user-facing route in both portals, auto-generating the screenshot-to-test-case mapping so CI-
produced PDF reports embed real browser-captured images, and running the full 64-scenario regression
suite with structured evidence output. It builds on the `v0.20.2` opt-in request logging correction
and the public graduate portal work merged from PR #62.

## Scope

- Expand `scripts/user-guide/capture-screenshots.ts` to cover 11 previously-missing routes: graduate
  profile, consent form, AI mentor, public graduates directory, recruiter landing, recruiter
  verification, graduate portfolio, admin submissions list, organizations, recruiter-requests, and
  program creation form.
- Auto-generate `screenshots-map.json` in the evidence directory so `generate-e2e-report.ts` embeds
  screenshots into the PDF without manual mapping.
- Run full regression suite (`regression:all`): 64 scenarios, 62 passed, 1 failed, 1 skipped.
- Generate E2E evidence PDF (5.5 MB, 77 embedded screenshots, PII-masked).
- Update user guides with new screenshots for the graduate portal, consent, and recruiter flows.

## Out of Scope

- Fixing the 1 failing scenario (`Full business E2E: Applicant → Admin → Mission → Submission →
  Public profile`) — root cause is a Playwright browser-context lifecycle issue, tracked separately.
- Implementing the skipped `storage: Storage browser upload/download scenario` — deferred to a
  storage-focused slice.
- Adding new browser-driven regression scenarios for DB-only areas (missions, journal, tenant) —
  tracked as a coverage gap, not addressed this iteration.

## Test Scenarios

- **Scenario**: All 44 portal routes have fresh screenshots captured by Playwright.
  - **Actor**: CI / developer running `capture-screenshots.ts`.
  - **Preconditions**: Local Docker stack running, demo data seeded, Ops console on port 3300.
  - **Steps**: Run `npx tsx scripts/user-guide/capture-screenshots.ts --evidence-run-id=<runId>`.
  - **Expected result**: 43 screenshots captured (4 skipped due to missing seed data — no published
    graduate profile, no journal entries, no pending recruiter requests). All 11 new routes captured.
  - **Automation**: Added this iteration (`capture-screenshots.ts` dashboard + public + admin + adminflows sections).

- **Scenario**: E2E PDF report embeds screenshots via auto-generated screenshot map.
  - **Actor**: CI / developer running `generate-e2e-report.ts`.
  - **Preconditions**: Regression results JSON, screenshots, and `screenshots-map.json` in evidence dir.
  - **Steps**: Run `npx tsx scripts/ci/generate-e2e-report.ts .ops/regression-results docs/user-guides/screenshots docs/reports --pii=mask`.
  - **Expected result**: HTML report contains 77 `<img>` tags with `data:image` URIs. PDF is 5.5 MB
    with all screenshots visible. PII is masked (emails, cookies, tokens redacted).
  - **Automation**: Added this iteration (`generate-e2e-report.ts` + `screenshots-map.json`).

- **Scenario**: Full regression suite runs with 64 scenarios and produces structured evidence.
  - **Actor**: CI / developer running `npm run regression:all`.
  - **Preconditions**: Full Docker stack (Postgres, Keycloak, MinIO, both portals, Ops console).
  - **Steps**: Run `npm run regression:all` with `REGRESSION_CLEANUP_ON_EXIT=1`.
  - **Expected result**: 62 passed, 1 failed (full business E2E — browser context closed), 1 skipped
    (storage upload/download). Per-scenario JSON evidence, HTTP capture, and gaps.json written.
  - **Automation**: Added this iteration (`regression:all` — existing suite, new evidence output).

- **Scenario**: Screenshot coverage gap audit — no user-facing route missing a screenshot.
  - **Actor**: Developer auditing route coverage.
  - **Preconditions**: All `page.tsx` routes enumerated from both apps.
  - **Steps**: Compare route list against captured screenshots.
  - **Expected result**: 44 routes total. 40 captured. 4 unmapped due to seed data gaps (not code
    gaps). 2 error pages (`/access-denied`, `/forbidden`) intentionally skipped.
  - **Automation**: Deferred — manual audit this iteration; should be automated as a script next.

## Security and Data Rules

- PII masking is enforced in the PDF report generator (`--pii=mask`): cookies, authorization headers,
  JWT tokens, OAuth codes, emails, and UUIDs are redacted before embedding.
- Screenshots are captured against the local demo tenant only — no real user data is included.
- The `screenshots-map.json` contains no sensitive data — only filenames, test-case IDs, and captions.
